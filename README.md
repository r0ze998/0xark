## 1. 着想

ハンター×ハンターの「グリードアイランド」を、Crypto Games（Dark Forest等）のような期間限定オンチェーンゲームとして再構築する。

**なぜこの組み合わせか：**
- GIの設計は本質的にAutonomous Worldsの原型（カード発行上限、PvP経済、資産ブリッジ）
- 期間限定にすることでFOMO効果＋経済の自然循環が生まれる
- ZKで手札を隠せるStarknetだからこそ成立する情報戦
- 「ポンジではない、遊びたいから参加する」構造が実現できる

## 2. 原作分析: グリードアイランド

### 概要
HxHに登場する架空のゲーム。ジン＝フリークス含む11人のゲームマスターが念能力で創った現実世界に存在するゲーム。

### 基本ルール
- プレイヤーは実際にゲーム世界に入る（念で作られた島）
- **指定ポケットカード100枚を集めるのがクリア条件**
- カード化できるアイテムは最大制限あり（全プレイヤーで共有）
- 死んだらリアルに死ぬ

### カードシステム

**カードランク（S〜H）:**

| ランク | 希少度 | カード変換上限（グローバル共有） |
|--------|--------|-------------------------------|
| SS | 最高 | 3枚程度 |
| S | 極レア | ~10枚 |
| A | レア | ~20枚 |
| B〜H | 段階的に緩い | 数十〜数百枚 |

**重要な設計ポイント:**
- カード化上限は**グローバル共有**。誰かがカード化してたら他の人はできない
- 同じカードの所持上限は**1人3枚まで**
- カードを現物化（アイテムに戻す）すると、その分カード化枠が空く

### バインダー構造
```
指定ポケット: 100スロット（No.001〜100）
  → 特定のカードしか入らない
  → 100枚コンプ = ゲームクリア

フリーポケット: 45スロット
  → 呪文カード・余剰カードを自由に格納
  → 満杯だと新しいカードを取れない（在庫管理が戦略に）
```

### 呪文カード

**攻撃系:**
- 窃盗（ピック・ポケット）: 相手のフリーポケットからランダムに1枚奪う
- 強奪（レバレッジ）: 相手の指定ポケットから狙ったカードを奪う
- 突撃（アタック）: 相手プレイヤーの元に強制転移して直接対決
- 複製（クローン）: 対象カードをコピー（ランク制限あり）

**防御系:**
- 防壁（ディフレクション）: 呪文攻撃を1回無効化
- 聖騎士の首飾り: 一定期間すべての呪文攻撃を防ぐ
- 堅牢（フォートレス）: 指定カード1枚を奪取不可にする

**移動・探索系:**
- 磁力（マグネティックフォース）: 特定プレイヤーの元に移動
- 同行（アカンパニー）: 特定の場所・人の元へ飛ぶ
- 漂流（ドリフト）: ランダムな街に飛ぶ
- 交信（コンタクト）: 離れたプレイヤーと会話

**取引系:**
- 交換（トレード）: 互いの同意でカード交換
- 贈呈（ギフト）: 一方的にカードを送る
- オークション: 複数人間での競売

### AWとの親和性
- カードの発行上限 → NFTの希少性
- プレイヤー間のカード奪い合い → PvPのオンチェーン経済
- ゲーム内アイテムが現実世界に持ち出せる → ブリッジ
- ルールはゲームマスターが設計、プレイヤーの行動は自由 → 自律世界

## 3. 設計哲学

### 🍄 任天堂（宮本茂）式 — 手触り至上

- **出発点は「手触り」**: 前に遊んだゲームをより豪華にするのではなく、「身の回りの何をゲームにしたら面白いか」から始める
- **最初の30分に全力**: 方向性と手触りを固めるのが最優先
- **プロトタイプ→触って判断**: 企画書じゃなく、まず触れるものを作る。面白くなければ「ちゃぶ台返し」
- **小規模でも磨きがいのあるユニークなソフト**: 開発費の大小より「何を作るか」が大切

```
コンセプト（何が新しいか？）
  ↓
プロトタイプ（最小限で手触り確認）
  ↓
ちゃぶ台返し（面白くなければやり直し）
  ↓
本開発（面白さが証明されてから規模拡大）
  ↓
デバッグ・ポリッシュ（最後の磨き込みに時間をかける）
```

### ⚔️ フロムソフトウェア（宮崎英高）式 — ビジョンと引き算

- **ビジョンドリブン**: ディレクターの世界観が絶対。全員がその方向に向かう
- **死にゲーの設計哲学**: 難しさは「理不尽」ではなく「学習可能」。プレイヤーが死んで覚える→達成感が最大化
- **環境ストーリーテリング**: テキストで説明しない。アイテムの説明文、建築、配置で物語を語る
- **引き算のデザイン**: チュートリアル最小限、マップ表示なし、ミニマルなUI

### 0xARKの設計原則

> **触って面白い最小限のものを、ブレないビジョンで磨く。説明しない、足さない、削る。**

1. 「カードを引く」「呪文を唱える」の1アクションが気持ちいいか？
2. チュートリアルは最小限。島に放り込んで「生き延びろ」
3. ルールはテキストで説明しない。触って覚える
4. 情報は隠す。マップは自分で歩いて発見する
5. 不親切だが不公平ではない — ルールは全員に平等
6. プロトタイプで面白さが証明されるまで機能を増やさない

## 4. ゲーム概要

**一言**: ZKで手札を隠した、期間限定オンチェーンPvPカード奪い合いゲーム

**エレベーターピッチ**:
プレイヤーは期間限定の島に放り込まれ、100枚のカードを集めてクリアを目指す。カードは探索・戦闘・トレードで手に入るが、呪文カードで他プレイヤーから奪うこともできる。誰が何を持っているかは見えない。同盟も裏切りも自由。シーズン終了時、生き残った者だけがカードを現実に持ち出せる。

**コアエクスペリエンス**:
「あいつが持ってるはず」という推理と、「奪われるかもしれない」という緊張が常に共存する。

## 5. コアループ

```
探索（島を歩く、街を訪れる）
  ↓
遭遇（モンスター / アイテム / 他プレイヤー）
  ↓
判断（戦う / 逃げる / 交渉する / 呪文で奪う）
  ↓
獲得 or 喪失（カードが増える or 減る）
  ↓
管理（バインダー整理、呪文温存、次の行動計画）
  ↓
探索へ戻る
```

**1セッション**: 10〜20分で意味のある判断が1回以上発生する

### プレイヤーモチベーション（バートルの4分類）

| タイプ | 欲求 | 0xARKでの居場所 |
|--------|------|-----------------|
| 🗡️ キラー | 他人に勝ちたい | 呪文PvP、強奪 |
| 🏆 アチーバー | コンプしたい | 100枚収集、クリア |
| 🔍 エクスプローラー | 発見したい | マップ探索、隠しエリア |
| 💬 ソーシャライザー | 交流したい | トレード、同盟、裏切り |

## 6. システム設計

### 6.1 プレイヤー
- バインダー（指定ポケット100 + フリーポケット45）
- 位置（マップ上の現在地）
- ステータス（最小限 — 死の概念はカード全喪失で表現）

### 6.2 カード
- **指定カード（100種）**: コンプ対象。各カードにグローバル発行上限
- **呪文カード**: アクション実行用。使い捨て
- **所持上限**: 同一カード3枚まで
- **カード化/現物化**: アイテム↔カードの変換。カード化枠はグローバル共有

### 6.3 呪文（初期は6〜8種に絞る）

**攻撃:**
| 呪文 | 効果 | 対抗手段 |
|------|------|----------|
| 窃盗 | 相手のフリーポケットからランダム1枚奪取 | 防壁 |
| 強奪 | 相手の指定ポケットから狙い撃ち | 堅牢 |
| 偵察 | 相手のバインダー内容を一部覗く | — |

**防御:**
| 呪文 | 効果 |
|------|------|
| 防壁 | 呪文攻撃を1回無効化 |
| 堅牢 | 指定カード1枚を一定期間奪取不可 |

**移動:**
| 呪文 | 効果 |
|------|------|
| 転移 | 指定の街へ瞬間移動 |
| 追跡 | 特定プレイヤーの元へ移動 |

**取引:**
| 呪文 | 効果 |
|------|------|
| 交換 | 双方合意でカード交換 |
| 贈呈 | 一方的にカード送付 |

### 6.4 ZK（情報秘匿） — 最大の差別化

- 手持ちカードは他プレイヤーから見えない
- 「強奪」で狙い撃ちするには、推理か偵察が必要
- 呪文の使用履歴はオンチェーンで公開 → 行動パターンから推測可能
- **知っている情報そのものが武器**
- Starknetのネイティブ証明システムで実装

### 6.5 マップ
- 島に複数の街・ダンジョン・フィールドが点在
- 各エリアで入手できるカードが異なる
- **マップは最初は空白。歩いた場所だけ見える（フロム式）**
- 他プレイヤーの位置は見えない（ZK）

## 7. シーズン設計

### 構造
- **1シーズン = 2〜4週間**
- 参加人数上限あり（例: 50〜100人）
- エントリーにトークンステーク必要

### 終了条件
1. **誰かが100枚コンプ** → 即時終了
2. **制限時間切れ** → カード保有数ランキングで順位決定
3. **全員脱落（カード0枚）** → 誰も持ち出せない

### 持ち出し（=最大のフック）
- **クリア者**: 指定カード3枚を永続NFTとして持ち出し
- **上位者**: 1〜2枚持ち出し
- **参加者全員**: シーズン参加証明NFT
- 持ち出しカードは次シーズン以降で特殊効果を持つ可能性（TBD）

### リセット
- カード・バインダー・マップ進行 → 全リセット
- 持ち出しNFT・実績 → 永続

## 8. 経済設計

```
参加ステーク
  ↓
シーズン中: カードトレード手数料
  ↓
シーズン終了: クリア報酬 + 持ち出しNFT
  ↓
持ち出しNFTの二次流通
  ↓
次シーズンの参加ステークへ
```

**ポンジではない理由**: ゲームプレイ自体に価値がある。報酬目的でなく「遊びたいから参加する」構造。r0zeが課題意識を持つ「脱ポンジの持続可能なトークノミクス」に直接応える設計。

## 9. 技術スタック

| レイヤー | 技術 |
|---------|------|
| スマートコントラクト | Cairo（Starknet） |
| ゲームフレームワーク | Dojo（ECSアーキテクチャ） |
| ZK | Starknetネイティブ証明 |
| フロントエンド | React |
| テストデプロイ | Slot |
| 本番デプロイ | Starknet Mainnet |

### ECS設計（Dojo）

**Models:**
```
Player    { address, position, binder_id }
Binder    { designated_slots[100], free_slots[45] }
Card      { card_type, rank, global_count, max_count, owner }
Spell     { spell_type, owner, used }
Location  { x, y, area_type, available_cards[] }
Season    { id, start_time, end_time, player_count, status }
```

**Systems:**
```
MoveSystem      — プレイヤー移動
ExploreSystem   — エリア探索→エンカウント
BattleSystem    — モンスター戦闘→ドロップ
SpellSystem     — 呪文発動→防御判定→効果適用
CardSystem      — カード化/現物化/トレード
SeasonSystem    — シーズン開始/終了/持ち出し処理
```

### オンチェーン設計の課題と対策

| 課題 | 対策 |
|------|------|
| リアルタイム戦闘のレイテンシ | Commit-Reveal方式 or オフチェーン処理 |
| マップ探索の処理負荷 | Dojo ECSで効率化 |
| ブロックチェーンの透明性（手札バレ） | ZKプルーフで秘匿 |
| 呪文の即時性 | 非同期PvP設計（ターン制寄り） |
